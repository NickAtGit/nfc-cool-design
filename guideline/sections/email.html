Every NFC.cool product sends mail in one style: the wordmark on a white card, one heading, a few lines, one blue button, small print under it, the product in the footer. A template does not write that markup. It hands renderEmail a list of blocks and gets back the HTML and the plain text, both from the same data.

A sign-in link

One action, then its fallback, then the small print. The button is the gradient's dark stop with a white label (5.82:1). A mail has no hover state to rescue the web button's 3.48:1 resting label, so the mail uses the blue that already carries link text. In dark mode it is brand yellow with an ink label, exactly as on the web. The link under the button breaks anywhere, so a long token never widens the card on a phone.

A notification

Somebody's own words sit on their own panel. An album's title is quoted on the page colour with a blue edge, so it reads as the album and not as part of the sentence, and a title full of <script> or quotes arrives as text: everything is escaped.

The API

import { renderEmail } from '@nfccool/design/email.js';

const { html, text } = renderEmail({
  assetBaseUrl: 'https://moments.example.com/email/',   // where the two wordmark PNGs are hosted
  lang: 'en',                                           // optional, default 'en'
  dir: 'ltr',                                           // optional, 'rtl' flips every side
  preheader: 'This link works once and expires in 15 minutes.',
  heading: 'Sign in to Moments',
  blocks: [
    { type: 'text', text: 'Tap the button below to sign in. It works once and expires in 15 minutes.' },
    { type: 'button', label: 'Sign in', href: link },
    { type: 'link-fallback', href: link },
    { type: 'note', text: 'If you did not ask for this, you can ignore this email.' },
  ],
  footer: {
    product: 'Moments by NFC.cool',
    reason: 'You got this because someone asked to sign in to Moments with this address.',
    links: [{ label: 'Terms', href: termsUrl }, { label: 'Privacy', href: privacyUrl }],
  },
});
// Send html and text together as multipart/alternative.
BlockWhat it is
{ type: 'text', text }A paragraph of body copy. text is a string, or runs: ['Restore it ', { text: 'here', href }, '.'], { text, strong: true }.
{ type: 'button', label, href }The one action. Bulletproof in Outlook desktop: the whole pill is the link.
{ type: 'link-fallback', href }"Or copy this link:" and the raw URL. Give label to translate it.
{ type: 'note', text }Muted small print: a deadline, "if you did not ask for this".
{ type: 'quote', text }A title set apart on its own panel, such as an album's name.
{ type: 'divider' }A hairline between the action and the small print.
The renderer owns all markup and styling; a template owns words and links. There is no style option and no raw HTML block on purpose: a mail that needs one is a gap in this system, and belongs here first. A link that is not http(s) or mailto throws, rather than shipping a button that does nothing.

The rules

One button per mail. Everything else is text or a note. Two blue buttons make the reader choose.
The heading says what happened, in the reader's words. "Set a new password", not "Password reset request".
The preheader finishes the subject. It is the grey line an inbox shows after it; do not repeat the heading.
Every mail says why it came. The footer's reason: "You got this because you own this album."
Write it once in plain text too. You do not: text comes from the same blocks, the button as "Label: URL", the fallback dropped when the button already carries its URL.
House style per product. MomentoMarks writes no em dash in any string a person reads; its examples here follow that. The renderer does not impose it.

Colour and dark mode

Every colour is a token. build/emit-css.mjs resolves a small role table (page, card, border, heading, text, muted, link, button) against src/tokens.json for both themes into src/email/palette.js, as flat literals: mail clients strip custom properties. The light values are inline on every element; the dark ones are a prefers-color-scheme block keyed on classes (Apple Mail, iOS Mail, Outlook for Mac, Thunderbird), repeated under [data-ogsc] and [data-ogsb] for Outlook.com. Gmail's apps invert a light mail on their own; the wordmark carries a hairline halo in its card colour so its ink letters survive that.

Hosting the wordmark

Gmail blocks SVG and no client loads a webfont reliably, so the header is a PNG, in two variants at 2x: wordmark-on-light.png and wordmark-on-dark.png, shipped as @nfccool/design/email/wordmark-on-light.png and …/wordmark-on-dark.png. The consumer serves both from one public https folder it controls and passes that folder as assetBaseUrl. Keep old files up once a mail has gone out: a mail sitting in an inbox fetches its image every time it is opened. Without assetBaseUrl, or with brand: { wordmark: false }, the header is the brand name in bold text. They are drawn from the repo's own logo by npm run email:assets.

From Django

Django takes generated templates, not a port. npm run build writes dist/email/django/: layout.html and one partial per block, each made by rendering src/email.js with placeholders, so the markup cannot drift. Vendor that folder into a templates directory as nfccool_email/ and the two PNGs into static files. A mail extends the layout; Django's autoescape does the escaping. It writes no plain-text part (keep a .txt template, as for subjects) and does not validate links, so build them with reverse() and build_absolute_uri(). 
{% extends "nfccool_email/layout.html" %}
{% block preheader %}This link works once and expires in an hour.{% endblock %}
{% block heading %}Set a new password{% endblock %}
{% block content %}
  {% include "nfccool_email/text.html" with text="Tap the button to choose a new password." %}
  {% include "nfccool_email/button.html" with label="Choose a new password" href=reset_url %}
  {% include "nfccool_email/link_fallback.html" with href=reset_url %}
  {% include "nfccool_email/note.html" with text=ignore_note %}
{% endblock %}
{% block footer_product %}NFC.cool{% endblock %}
{% block footer_reason %}
  You got this because someone asked to reset the password for this address.
{% endblock %}
