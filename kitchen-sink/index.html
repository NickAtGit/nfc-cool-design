NFC.cool Design System —

Every element, with its basis

This page renders every token, component and marketing archetype in the system. Each specimen carries a basis note saying which tokens it consumes, where it came from, and what decision it encodes. Contrast ratios are measured live in your browser from the actual computed values, so they stay honest if a token changes.

Toggle Dark and RTL in the bar above, and resize the window: the breakpoint readout tells you which of the four is active. Badges mark what is kept from the live nfc.cool site, new in this system, and changed from what ships today.

The one blue gradient

Why this one. It is what the iOS app renders, and it is the darkest of the five that were in circulation, so white clears AA at the top stop and stays above the 3.0 large-text floor at the bottom. Every retired alternative dropped below 3.0 before its band ended.

The shadow stays, and it is not a hack. Brand Manual V1, page 10, on the secondary logo: the "NFC" element in white and ".cool" in the brand's yellow, and "both elements should always be used with the designated shadows." --on-brand-text-shadow is a brand requirement that also happens to carry body copy over the lower half of the band.

1. Colour

Two themes. The mode flip is deliberate and preserved: interactive elements are brand blue in light mode and brand yellow in dark. Yellow is never text on a light surface.

Surfaces

Basis. --color-bg-alt is changed: on the live site it is identical to --color-bg in both themes, so the alternating section rhythm is a no-op maintained by nine CSS rules. It now carries a real one-step value, and the muted text token was nudged so it still clears 4.5:1 on that darker surface.

Text

Basis. Values inherited from the live site, except --color-text-muted, which moved from #686F76 to #666D74 so it survives the new --color-bg-alt. A two-point nudge, invisible in use.

Interactive

Basis. changed, and this fixes three measured failures on the live site. --color-link stays #137BD9 as the interactive hue for borders, chevrons and hover fills. A new --color-link-text carries actual link text, because #137BD9 measures 3.99:1 and inline links in prose are body copy. The live hover colour #00A2F3 is 2.60:1, meaning hovering a link today makes it less readable; --color-link-text-hover darkens instead.

Brand

Basis. The gradient is changed. On the live site it runs #137BD9 → #00A2F3, where white text measures 4.32:1 at the top and 2.81:1 at the bottom, below even the 3:1 large-text floor. That is why every hero headline carries text-shadow: 0 1px 1px rgba(0,0,0,.55) and every subtitle is set to rgba(255,255,255,.92): the site is compensating for a failure. Both stops were darkened within the same hue until white clears 4.5:1 across the whole band, and the compensation can go.

The script tail is expected to fail and is marked exempt: WCAG 1.4.3 exempts text that is part of a logo or brand name, and this renders the brand name. It is one token so the call can be revisited, but the pattern must never be copied onto ordinary text.

Semantic tones

Basis. new. The live site has one --color-success and a single inline #DC2626; the pricing pills each invent their own green, red, amber and orange. business_card_service has three unrelated alert systems with three different green/red pairs. This is one ramp of foreground, background and border per tone.

2. Typography

One family, Titillium Web, at three weights, with Caveat as the script accent. The ramp below collapses roughly fourteen unique clamp() expressions from the live stylesheets into a named ladder.

Basis. kept - every size is a value already in use, just named. The two tracking directions are the system's real signature and are now tokens: negative on display sizes (--tracking-hero, --tracking-display), positive on uppercase micro-labels (--tracking-label, --tracking-eyebrow). 3. Space, shape, elevation, motion

Space scale

Basis. new - the live site has no spacing scale at all. A 4px grid, but it deliberately keeps --space-5: 1.25rem (20px), which is off an 8px grid and is nfc.cool's signature card-grid gap. Dropping it would re-space every grid on the site for no gain.

Radius

Basis. kept - nfc.cool's existing six, unchanged. --radius-md (10px) matches the App Store badge corner, which is why buttons use it.

Elevation

Basis. Six ad-hoc shadows in the shipped CSS become four steps. --elev-media is the house treatment for product renders: a cool blue-tinted double shadow by day that becomes a warm accent glow at night. Toggle the theme to see it invert.

Motion

Hover: lift 2
Linked: lift 3
Basis. kept. The vocabulary is deliberately tiny: one duration (--transition: .2s ease) and one gesture, a hover lift, in three tiers. No scroll animation, no reveal-on-scroll, no entrance choreography. Under prefers-reduced-motion all three lift tokens collapse to 0.

4. Buttons

One component parameterised by six local custom properties, so the same element re-skins by context instead of forking into a variant per surface.

Tiers

Basis. The filled primary is new and it is the single biggest gap being closed. The live nfc.cool site has no filled button anywhere - its real primary CTA is an App Store badge, which works only when the conversion is "leave for the store". It has no answer for Save, Invite, Delete, or the card page's Save Contact. business_card_service filled that vacuum with five different button designs across five surfaces. The outlined tier is the shipped .landing-cta-button, unchanged.

One blue, used as an area. The filled tier fills with #128CF0 and the outlined tier borders with the same value, so they read as one family. White on that fill is 3.48:1, under the 4.5 a 15px label needs; it is a deliberate decision, pinned in the contrast suite with its date so it stays revisitable rather than becoming an invisible regression.

Hover darkens to #0F76CA, which lifts the label to 4.70:1, so the state a person is actively pointing at is the compliant one. The test does not pin a direction, it pins the outcome: hover must never make the label harder to read. In dark mode, where the primary is brand yellow with a near-black label, that same rule makes hover brighten instead.

If it is ever revisited, #0F78CE is the nearest shade of this blue where a white label clears 4.5 at rest.

Sizes and states

One blue on a button. Blue as an area is the light stop; blue as text is the dark stop. On a button the blue is always a fill or a border and never the label, so Save and Cancel border and fill in the same #128CF0. Cancel's label is ink rather than blue: a blue label beside a blue border is two blues on one control, and the light stop is only 3.48:1 as text anyway. A border is a UI boundary, so 3:1 applies and it clears at 3.48. Ghost has no border, so its label carries the affordance and takes the dark stop, like an inline link.

Basis. Every state is defined, including :focus-visible - tab through them. On business_card_service the primary CTA has :hover, :focus and :active all forced back to the resting state with !important, so the most important button in the product has no visible keyboard focus. That is the worst accessibility defect across the three properties and this replaces it.

On a brand band

Basis. Adding .on-brand re-points the button's local properties. No new classes, no duplicated rules - this is the mechanism nfc.cool already uses for its on-gradient CTA, generalised to the filled tier and to focus rings.
